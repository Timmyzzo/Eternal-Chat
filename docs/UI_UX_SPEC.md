# UI/UX 规格

## 1. 设计目标

界面必须具有现代感，同时保持高频工作工具所需的清晰和效率。现代感不等于营销式首屏或装饰渐变，而是来自精确排版、即时反馈、连续可中断的交互、稳定空间关系、克制材质和可深度客制化的工作流。

## 2. 设计原则

- 关键状态可见：当前模型、是否在生成/等待重试、是否在思考/搜索、工具是否成功、上下文是否被调整。
- 默认界面简单，高级配置通过右侧面板、抽屉或开发者模式进入。
- AI 正文使用无框阅读布局，避免长 Markdown 被困在气泡卡片中。
- 工具、搜索和思考是结构化内容，不混成一大段 Markdown。
- 不为装饰制造卡片嵌套、渐变光球、过大标题或营销式首屏。
- 图标按钮优先使用 lucide-react，并为不熟悉的图标提供 tooltip 和无障碍名称。
- 所有动态区域有稳定尺寸约束，流式内容不能让工具栏和输入区跳动。
- Provider、模型和公司名称不决定控件能力；界面只展示当前 endpoint/profile/schema 的实际配置。
- 常用路径优先，但高级字段、raw request、工具 descriptor 和响应 mapping 始终可达。

### 2.1 流体交互原则

- **即时响应**：按钮、分段控件和列表项在 pointer-down 时给出视觉反馈，不等 click 完成。
- **连续反馈**：拖拽侧栏、调整面板和滑动抽屉时内容与指针 1:1 跟随，并保留抓取偏移。
- **可中断**：任何可交互元素的动效都能在当前屏幕位置被抓住、反向或重新定向；过渡期间不锁输入。
- **速度继承**：拖拽释放后的吸附继承手势速度，先投影落点，再用 spring 收敛。
- **空间一致**：面板从触发源展开，进入和退出沿同一路径；关闭后焦点返回原触发控件。
- **边界阻尼**：可拖拽区域越界时使用渐进阻力，不突然冻结。
- **行为优先**：默认 spring 使用接近临界阻尼、无装饰性弹跳；只有 flick/throw 等带动量手势才允许轻微 overshoot。
- **感官克制**：声音、震动或强调动效只用于明确完成、失败和提交，且与视觉状态同帧发生。

## 3. 信息架构

```text
┌──────────────┬────────────────────────────────┬──────────────────┐
│ 会话侧栏      │ 聊天主区                        │ 按需右侧面板       │
│              │                                │                  │
│ 新建/搜索     │ 顶部：标题、模型、状态           │ 参数              │
│ 最近/置顶     │ 消息虚拟列表                    │ 上下文检查器       │
│ 归档          │ 思考/工具/来源/正文              │ 搜索过程详情       │
│ 设置入口      │ 回到底部按钮                    │ 会话信息           │
│              │ 输入区                          │                  │
└──────────────┴────────────────────────────────┴──────────────────┘
```

- 左栏默认约 260px，可折叠。
- 中间正文列 `max-width` 约 48rem，但工具/来源详情可在更宽区域或右侧面板展示。
- 右侧面板按需出现，不常驻占用小窗口空间。
- 小窗口隐藏右侧面板并以抽屉显示；左侧栏可覆盖式打开。

## 4. 视觉令牌

使用中性基础、清楚语义色和有限品牌强调色，但不能把界面做成单一色相。实现前先定义 CSS variables：

- 背景：页面、面板、hover、选中、代码区、错误区。
- 前景：主文字、次文字、弱文字、反色文字。
- 语义色：成功、警告、错误、信息，不用强调色冒充所有状态。
- 边框：常规、聚焦、分隔。
- 圆角：紧凑控件和卡片不超过 8px；页面区块不包装成浮动卡片。
- 间距：8px 网格为主，紧凑列表允许 4px 子级间距。
- 字体：优先系统字体和 optical sizing；letter-spacing 保持 `0`，通过字号、字重和行高建立层级。
- 动效：交互型位移使用可重定向 spring，默认 damping ratio 约 `1.0`、response `0.3-0.4s`；简单 opacity/color 反馈可使用短过渡。
- 材质：半透明只用于悬浮导航、工具栏、popover 和 sheet 等功能层，不叠放浅色玻璃卡片。

文字不使用基于 viewport width 的连续缩放。按钮、标签和卡片内的最长模型名必须能换行、截断并提供完整 tooltip，不能撑破容器。

### 4.1 动效与减少动态效果

- gesture-driven 动效使用 Motion/Framer Motion 等支持当前值、速度和 retarget 的 spring 能力，不使用无法中途接管的长 `@keyframes`。
- 拖拽释放时传递实际速度，X/Y 轴独立处理。
- 动画只更新 `transform` 和 `opacity` 等合成友好属性；动态内容不能改变工具栏、计数器和输入区的固定尺寸。
- `prefers-reduced-motion` 下取消弹性、视差和大位移，改用短 cross-fade 或即时状态切换。
- `prefers-reduced-transparency` 下提高材质不透明度并移除 blur；高对比模式增加清晰边界。

### 4.2 个性化令牌

用户可以按全局、工作区或会话作用域配置：

- light/dark/system 和自定义主题色板。
- UI 字体、正文字体、代码字体、字号、行高和阅读列宽。
- compact/comfortable/spacious 密度。
- 左侧栏宽度、右侧面板宽度、面板默认位置和是否自动折叠。
- 用户/AI 消息对齐、背景强度、元信息显示和正文最大宽度。
- Markdown、代码高亮、数学公式和引用显示偏好。
- 思考、工具、来源、usage 和错误详情的默认折叠策略。
- 动效强度、滚动行为和快捷键。

所有个性化选项提供即时预览、恢复当前作用域默认值和重置全部功能；切换主题不能造成整页亮度突变。

### 4.3 UI 语义契约

核心界面在 app-owned DOM 边界上使用一个稳定的 `data-ui` 属性，值为由空格分隔的静态语义 token；可复用组件内部结构继续使用 `data-slot`，必要时同时投影为 `part:*` token。该契约服务自动化测试、诊断检查器和未来高级个性化，不要求 MVP 立即开放任意自定义 CSS。

```html
<article data-ui="chat.message">
  <div data-slot="message-content" data-ui="part:message-content"></div>
</article>
```

规则：

- 业务 token 使用小写点分名称，例如 `chat.message`、`chat.composer.action.send`；结构 token 使用 `part:*`。
- 长期稳定的业务边界必须显式声明，不从文件名、CSS class、可见文案、翻译文本、行号或随机 ID 自动生成。
- CSS/测试使用 token 匹配 `[data-ui~='chat.message']`，不得使用 substring 选择器。
- E2E 从 `data-ui`/`data-slot` 定位业务区域，再使用 accessible role/name 完成具体交互；`data-testid` 只用于无法表达的测试内部状态。
- 显式 token 和 `part:*` 是兼容接口。重命名时至少保留一个发布周期 alias，并记录 breaking change；普通内部 wrapper 和 DOM 层级不作稳定承诺。
- 不给每个 DOM 节点添加 token。只有业务边界、常用动作和跨组件稳定结构进入契约，避免形成第二套组件树。

MVP 初始 token 至少包括：

```text
app.window
app.sidebar
app.content
chat.view
chat.message-list
chat.message
chat.composer
chat.composer.action.send
chat.composer.action.stop
providers.view
providers.endpoint
settings.view
part:message-content
part:composer-input
part:composer-actions
```

本规范吸收 Cherry `ui-semantic-contract` 的稳定语义边界思想，但 MVP 使用显式维护，不引入自动扫描/推断插件。

## 5. 左侧会话栏

### 5.1 顶部操作

- 新建会话：图标按钮或图标+文字主命令。
- 搜索：可直接输入或打开命令面板。
- 侧栏折叠：标准 panel 图标，保持固定点击区域。

### 5.2 会话项

显示标题、更新时间和可选状态图标。模型名不在每条会话中重复显示，除非用户启用高级密度设置。

状态：

- 当前选中。
- 正在生成。
- 等待用户处理错误。
- 置顶。
- 归档。

hover 菜单提供重命名、置顶、归档和删除。删除是破坏性操作，需要明确对象名称和确认。

### 5.3 搜索结果

结果显示会话标题、命中片段、角色和时间。点击后打开对应分支并滚动到消息，焦点应落到命中消息，读屏获得状态通知。

## 6. 聊天顶部栏

- 左侧：会话标题，支持点击重命名。
- 中间或右侧：当前模型选择器。
- 状态区：连接、等待自动重试、生成、错误、离线或上下文警告。
- 更多菜单：导出、会话参数、系统提示词、归档、删除。

模型选择器显示真实配置名，不按模型 ID 粗略改写为可能错误的产品档位。可以显示 Provider 和能力摘要，但不能用显示名称决定请求参数。

## 7. 消息布局

### 7.1 用户消息

- 浅色块居右。
- 支持附件缩略信息。
- hover 工具：复制、编辑、从此处分支。
- 编辑不会覆盖已经有后代的原消息。

### 7.2 AI 消息

- 无框贴左，正文优化长阅读。
- 顶部可显示模型、时间和状态，默认弱化。
- 块顺序按实际事件与最终持久化结构渲染。
- hover 工具：复制、重新生成、切换 sibling、查看请求、反馈占位。

### 7.3 消息分支

有多个 sibling 时显示紧凑 `1 / 3` 控件和前后箭头。切换后整个后续路径随分支变化，不能只替换当前一条 AI 文本而保留错误后代。

## 8. 思考区域

### 8.1 流式中

显示：

- `思考中` 或 Provider 更准确的状态。
- 本地计时。
- 最近 1-3 个结构化事件。
- 多代理时的活动代理/rollout 指示，仅在 Provider 确实返回时显示。

区域高度必须有上限和内部滚动，不能无限推走最终答案。

### 8.2 完成后

折叠标题如 `思考了 42 秒`、`思考摘要` 或 `搜索与工具过程`。展开后保留完整事件，不只显示一条自动生成摘要。

### 8.3 真实性标识

详情面板应说明内容来源是 Provider 返回的 reasoning、summary、tool trace 或本地计时。不要使用会让用户误认为看到隐藏内部思维的文案。

## 9. 工具与搜索区域

### 9.1 工具条目

每个工具条目具有稳定头部：图标、名称、状态、耗时、展开按钮。状态使用图标和文字，不只依赖颜色。

展开内容：

- 参数或搜索 query。
- 模型可见结果。
- 可选原始结果入口。
- 错误详情。
- 来源列表。
- 是否会在下一轮上下文中回放。

### 9.2 搜索时间线

按实际事件顺序显示搜索、打开页面、结果返回和引用建立。多个并行工具调用可以按 agent/rollout 分组，但默认仍保留全局时间顺序入口。

### 9.3 信源

- 正文内引用使用紧凑域名/编号 pill。
- 消息尾部显示去重后的信源列表和数量。
- 点击引用定位来源详情，点击 URL 使用系统浏览器。
- X 帖子可显示作者、handle、时间和预览。
- 不可访问或过期 URL 标记状态，不从历史中静默删除。

## 10. 输入区

### 10.1 结构

- 多行文本输入。
- 左侧附件/工具入口。
- 当前会话参数的紧凑入口。
- 右侧发送或停止图标按钮。
- 不在输入框周围堆叠大段使用说明。

### 10.2 快捷键

- `Enter` 发送。
- `Shift+Enter` 换行。
- `Ctrl/Cmd+K` 命令面板。
- `Ctrl/Cmd+N` 新会话。
- `Esc` 关闭当前浮层；生成中不直接等同停止，避免误触。

允许在设置中切换 Enter 行为；默认使用 `Enter` 发送、`Shift+Enter` 换行。

### 10.3 流式时

输入框仍可编辑。默认可准备下一条输入，但是否支持“steer”进入当前运行流属于后续功能；MVP 发送按钮在当前请求完成前用于停止，不应悄悄排队发送。

## 11. 连接与端点配置界面

### 11.1 连接分组

- 连接名称和可选厂商提示。
- 端点数量、最近使用端点和默认模型。
- 添加、复制、排序、禁用端点。

### 11.2 端点普通模式

- 完整 Base URL，或 scheme/host/显式 port/base path 的结构化输入。
- path template 和 protocol profile。
- 认证绑定、连接测试、timeout 和自动重试基础设置。
- 最终 `host:port/path` 常驻预览。
- 模型列表、远程拉取和手工添加。

### 11.3 端点高级模式

- method、path variables、API version。
- protocol profile fork/编辑和 revision。
- auth placement、字段名、前缀和值引用。
- 自定义 Header。
- 自定义 Query。
- timeout。
- RetryPolicy：基础/最大延迟、总预算、HTTP/Provider 代码 allowlist。
- 请求/响应/流式事件/tool call mapping。
- Endpoint/模型/会话 raw Body/Header/Query。
- 完整请求预览和 profile diff。

高级模式中的 JSON 编辑器必须有语法错误位置和格式化操作，不用普通 textarea 承担复杂 JSON。

## 12. 参数面板

- 参数按生成、采样、推理、输出、结构化、工具、状态/缓存、调度和 Provider 特有字段分组。
- 每项显示友好语义、启用开关、placement、实际 wire path、当前值、来源和 compatibility 状态。
- 单独的“内置工具”分组，展示 UI 意图、实际 tool descriptor、tool choice 和 Provider 特有高级参数。
- “努力程度/思考预算”控件只提供语义和官方写法 tooltip；实际字段可以是 `effort`、`reasoning_effort`、`reasoning.effort`、`reasoningEffort`、`thinkingLevel`、`thinkingBudget` 或用户任意 path。
- 思考控件显示实际 endpoint/wire path；Grok 多代理在对应官方 preset 中显示代理数量语义，而不是笼统的低/高思考。
- 数字参数优先使用输入 + stepper，范围较明确时可附 slider。
- 布尔值使用 switch。
- 枚举使用 select，并提供自定义值入口。
- 未知官方范围允许输入，但显示非阻断提示。
- 每个参数显示最终来源：protocol、endpoint、model、conversation 或 raw override。
- `extra_body` 冲突时明确标出该表单值已被覆盖。
- 高级用户可以添加、复制、禁用、排序和删除任意参数，不需要等待应用更新。
- 参数探测结果以 `unknown / effective / ignored / rejected / translated` badge 显示，HTTP 200 不自动视为有效。

### 12.1 能力面板

能力面板覆盖输入/输出模态、streaming、reasoning、structured output、function tools、parallel tools、built-in tools、MCP、citations、logprobs、cache、server state、background 和 batch。`unknown` 使用中性状态，不显示成禁用。

### 12.2 交互细节

- 参数启用、禁用和覆盖在 pointer-down 后立即给出状态反馈。
- 从列表打开编辑 sheet 时以该参数行作为 transform origin；关闭沿相同路径返回。
- 拖动排序 1:1 跟随，释放时继承速度并吸附到稳定位置；reduced motion 下即时重排。
- 保存后不关闭整个高级面板，避免反复进入；字段错误就地定位并聚焦。

## 13. 上下文检查器

右侧面板或独立抽屉，分三个 tab：

1. `内容`：本轮消息与块，包含/排除状态。
2. `工具`：调用与结果配对、模型可见内容、raw artifact 状态。
3. `请求`：最终 URL/端口、protocol revision、序列化预览、参数来源、兼容状态、token 估算和 manifest hash。

普通用户只在上下文超限或工具连续性异常时被引导进入。开发者模式可从每条 AI 消息的更多菜单打开历史快照。

## 14. 空、载入与错误状态

### 14.1 空会话

直接显示输入区和简洁的最近模型/提示词入口，不做营销 hero。

### 14.2 初次无 Provider

显示一条明确的配置入口，并允许进入本地设置。不要展示不可用的假聊天界面。

### 14.3 加载历史

使用与消息布局近似的骨架，不移动输入区。

### 14.4 错误

错误块包含简短结论、重试按钮、配置入口和可展开详情。不得用浏览器 `alert`。

手动“重试/重新生成”创建新分支；它必须与自动 retry attempt 使用不同文案和状态语义，避免用户误以为每次网络尝试都产生了新回答。

### 14.5 等待自动重试

同一个 assistant placeholder 内显示紧凑状态条：

- `第 2 / 4 次尝试`。
- `429 请求过多`、`连接超时` 等稳定原因。
- 倒计时和等待来源：`Retry-After` 或本地退避。
- `停止`；没有服务端强制等待时可以显示 `立即重试`。

尝试历史进入可展开详情，不在聊天流中堆叠多张相同错误卡。存在 `Retry-After` 时禁用提前请求并说明原因。倒计时以低频更新，不得每帧触发整条消息重渲染；读屏使用节流状态，例如“将在 5 秒后进行第 2 次尝试”。

### 14.6 上下文超限

显示具体预算和选项，不只显示“内容太长”。

## 15. 滚动行为

- 用户位于底部且流式更新时自动吸底。
- 用户主动上滑后立即暂停吸底。
- 显示固定位置的“回到底部”图标/胶囊，含未读增量提示。
- 上方加载历史时保持可见锚点，不跳回顶部或底部。
- 分支切换、搜索定位和错误恢复均使用可控焦点与滚动。
- reduced motion 下使用即时滚动或极短过渡。

## 16. 无障碍

- 所有图标按钮有 `aria-label` 和 tooltip。
- 焦点样式清晰，键盘可完成 Provider 配置、模型切换、发送、停止、展开工具和分支切换。
- 流式正文不逐 token 触发读屏播报。使用节流的 `aria-live` 状态，如“回答完成”。
- 错误、成功和工具状态不只通过颜色表达。
- 折叠控件暴露 `aria-expanded`。
- Dialog/Drawer 正确管理焦点陷阱和关闭后焦点返回。
- 动画遵守 `prefers-reduced-motion`。

## 17. 窗口与响应式

建议验证视口：

- 1280x800 常规桌面。
- 1440x900 主开发视口。
- 1920x1080 宽屏。
- 900x700 小窗口。
- macOS 标题栏 overlay。

小窗口优先保留聊天正文和输入区，侧栏/右栏变为抽屉。模型名、按钮和输入工具不得相互重叠。

## 18. UI 验收

- 1000 条消息虚拟列表中，流式输入区仍可正常打字。
- 一条 5 万字回复和 20 个代码块不会撑破布局。
- Grok 搜索过程流式出现时，不导致消息宽度、输入区或侧栏跳动。
- 未知长模型名在所有选择器中不溢出。
- 工具失败、Provider 错误、取消和上下文超限都有独立可理解状态。
- 自动重试能显示 attempt、原因、倒计时和停止，最终成功不会产生重复 assistant 卡片。
- 键盘可以完成核心聊天流程。
- 核心页面、消息、输入框、发送/停止和 Provider 端点拥有稳定 `data-ui`/`data-slot`；E2E 不依赖 Tailwind class 或本地化文案定位区域。
- 浅色、深色、reduced motion 和高缩放比例下无重叠。

## 19. UI 验收补充

- pointer-down 有即时反馈，抽屉/面板/拖拽动效可在任意时刻打断和反向。
- 进入/退出路径一致，焦点能返回触发源。
- 同一连接的多个端口和协议在配置页清楚可比较，不依赖厂商图标区分。
- 任意参数都能看到语义标签和实际 wire path，两者修改互不隐式影响。
- 主题、字体、密度、阅读宽度、面板布局、折叠策略和动效强度可保存、预览和重置。
- translucent material 只用于功能层，不产生卡片嵌套或影响正文可读性。
- 深浅主题、减少动态效果、减少透明度、高对比和 200% 缩放下无重叠。
