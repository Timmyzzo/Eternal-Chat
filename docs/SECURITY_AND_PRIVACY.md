# 安全与隐私专题（延期）

## 1. 状态

- 当前状态：`deferred`
- 当前结论：安全、隐私和凭据治理暂不进入 Eternal Chat 的当前设计范围，也不阻塞脚手架、核心聊天或 MVP。

## 2. 当前不做

以下事项暂不锁定实现，不得作为当前阶段的隐藏前置条件或发布门禁：

- API Key、token、代理凭据和其他认证值的保存方式。
- keyring、系统钥匙串、加密数据库或明文配置之间的选择。
- Rust 或 TypeScript 中的认证注入边界。
- 日志脱敏、诊断包脱敏和请求快照的敏感字段保留策略。
- Markdown/远程内容威胁模型、WebView 权限隔离和 Tauri capability 审阅。
- 导入导出的敏感数据规则、加密备份和 WebDAV 凭据治理。
- 更新签名、插件签名、权限模型和供应链安全。
- 专门的安全测试、secret scan 或隐私合规工作。

核心架构目前只要求认证能通过可编辑 `AuthBinding` 参与最终 Header、Query 或 Body 装配；具体值如何取得、保存和删除以后再决定。

## 3. 当前仍保留的开发卫生

延期产品安全设计不等于把真实秘密写进开发材料。源码、文档、fixture、示例配置、测试报告和提交记录不得包含真实凭据或私人数据；统一使用明显的虚构占位值。

这条规则只保护共享开发资产，不代表产品已经完成任何安全承诺，也不形成运行时架构门禁。

## 4. 何时恢复

只有用户明确把安全与隐私重新纳入范围，或某个后续功能无法在不定义安全边界的情况下成立时，才创建新的专题设计。恢复时至少重新决定：

- 凭据生命周期和认证注入位置。
- 请求、日志、快照、导出和同步的数据保留边界。
- WebView、文件、网络、MCP 与插件权限。
- 更新、插件和分发完整性。
- 自动化测试与发布门禁。

恢复后的决定应以新 ADR 和迁移计划落地，不得把本延期文档当作既有实现承诺。
