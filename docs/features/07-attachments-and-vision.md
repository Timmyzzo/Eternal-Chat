# 附件与视觉模型

## 状态

- 里程碑：V1
- 当前状态：`deferred`
- 依赖：artifact 存储、消息块、protocol codec/profile、上下文检查器、文件选择

## 用户问题

用户需要把图片或文件作为真实输入交给模型，而不是只在界面中看到一个附件卡片。附件在发送、重试、分支、重启、导出和后续轮次中都必须具有可追踪的一致语义。

## 目标

- 支持通过文件选择、拖放和剪贴板添加本地附件。
- V1 首先完成视觉模型图片输入，并建立通用文件块和 artifact 基础。
- 使用内容哈希去重保存附件，消息只保存稳定引用和必要元数据。
- 由 protocol codec/profile 将附件转换为对应协议的输入项。
- 在请求前显示附件是否会进入模型上下文、预计大小和能力风险。
- 支持历史查看、重新发送、分支、导入导出和完整性检查。

## 非目标

- V1 不做知识库自动入库或 RAG；见 [知识库](./10-knowledge-base.md)。
- V1 不承诺 PDF、Office、音频、视频等所有格式都能被模型直接理解。
- 不在本地自动执行 OCR、宏、脚本或附件内嵌内容。
- 不把图片生成、图片编辑和语音处理混入本功能。
- 不根据内置模型名称白名单决定附件是否可用。

## 支持范围

### 图片输入

首个增量必须支持常见静态图片格式，并以实际 MIME、文件大小、像素尺寸和 Provider 限制进行预检。动画图片默认作为静态或不支持输入处理，具体行为必须显示，不能无提示改变。

### 通用文件

通用 `file` 块在 V1 建立存储、展示和导入导出语义。只有 codec/profile 明确支持的协议才允许把原文件直接发送给模型；否则必须显示“不支持直接发送”，不能只发送文件名或空占位符。

### 未知模型

模型目录中的视觉能力只是建议值。未知模型或用户手工添加的模型仍可尝试发送附件，UI 应显示“能力未确认”而不是禁用入口。Provider 拒绝时保留原始附件并显示脱敏错误，不自动改用其他模型或删除附件。

## 用户流程

1. 用户通过选择、拖放或粘贴添加附件。
2. 客户端在后台读取、计算内容哈希并进行类型、大小和安全预检。
3. 输入区显示稳定缩略图或文件条目、处理状态和移除按钮。
4. 发送前，客户端检查当前模型/端点是否已知支持该输入，并显示警告或阻断原因。
5. 消息与 artifact 引用在发起网络请求前事务化保存。
6. protocol codec 从 artifact 读取内容，按 profile 生成图片或文件输入项。
7. RequestSnapshot 和 ContextManifest 记录对应 message/block/artifact hash，但不复制文件正文。
8. 重新打开、重试或切换分支时，附件仍指向同一内容；若文件缺失则显示可诊断错误。

## 数据与生命周期

附件使用 [数据模型](../DATA_MODEL.md) 中的 `artifact`：

- `content_hash` 是去重与完整性校验依据。
- `relative_path` 由内部 ID 或 hash 生成，不能使用原始文件名拼接。
- 原始文件名仅用于显示，并清理控制字符。
- 消息 `image`/`file` 块保存 `artifactRef`、MIME、显示名、尺寸等协议无关元数据。
- 同一 artifact 可被多条消息或多个分支引用。
- 删除消息或会话后只减少引用；无引用文件进入延迟垃圾回收，不立即物理删除。

应用不得只保存源文件的外部绝对路径。用户移动或删除原文件后，历史消息仍应可用；导入前必须把允许的内容复制到应用数据目录。

## 上下文与 Provider 规则

- 图片/文件块属于规范消息历史，不从 UI 临时组件反推。
- 当前分支中应进入上下文的附件必须由 codec/profile 显式序列化。
- codec/profile 不支持某种块时必须返回具体错误，不能静默丢弃。
- Provider 使用上传文件 ID 时，本地仍保存 artifact；远端 ID 作为有作用域和有效期的 `provider_state`，不能成为唯一副本。
- 重试应复用同一 artifact，并按 codec/profile 规则决定是否复用有效远端 ID。
- 默认 `lossless` 策略同样适用于附件。超过请求大小或上下文预算时暂停发送并给出可见选择。
- 手工排除某个附件只影响该次或后续明确选择的上下文，不删除历史文件。

## UI 状态

- `processing`：读取、hash 或缩略图处理中，暂不可发送。
- `ready`：本地内容完整，可进行 Provider 预检。
- `capability_unknown`：模型能力未知，允许用户确认后尝试。
- `unsupported`：当前 codec/profile/端点明确不支持，阻止发送。
- `missing`：artifact 文件不存在或 hash 不符。
- `uploading`：协议需要预上传且正在执行。
- `failed`：读取、上传或 Provider 校验失败，可查看原因并重试。

缩略图不得改变输入区高度到不可控。大量附件使用固定尺寸、可横向浏览的列表；历史附件按需解码，不能一次加载整段会话的原图。

## 隐私与安全

- 文件只在用户明确添加后读取。
- 发送前应能看到哪些附件将离开本机以及目标 Provider。
- 不自动加载附件中的远程资源。
- 不在 WebView 中执行 PDF JavaScript、Office 宏、HTML 或 SVG 脚本。
- 文件名、MIME、尺寸和解码器输出均视为不可信输入。
- 设置单文件、单消息和本地总量上限；具体默认值在实现前结合 Provider 限制确定并写入测试。
- 临时转换文件位于应用专用目录，成功、失败和取消后都要清理。
- 导出包中的附件必须通过 manifest 和 hash 校验；导入时执行路径穿越、符号链接和解压大小检查。

## 性能

- hash、尺寸读取和缩略图生成不得阻塞输入线程。
- 缩略图使用受限尺寸缓存，原图只在预览或发送时读取。
- 相同内容只保存一份，不按消息复制大文件。
- 大文件读取和上传支持取消，取消后释放 reader、buffer 和临时文件。
- 历史列表只加载可视附件元数据和缩略图。

## 错误与恢复

- 文件读取失败：保留输入区条目和错误，不创建假 artifact。
- hash 不匹配：阻止发送和导出，提供重新导入原文件的入口。
- Provider 上传成功但消息保存失败：不得标记本轮成功，记录可清理的远端状态。
- 网络中断：保留本地附件，可安全重试。
- 远端文件 ID 过期：重新上传本地 artifact；本地缺失时明确失败。
- 导入包缺附件：导入其余内容前显示缺失清单，不生成空文件冒充成功。

## 自动化测试

- 文件选择、拖放、粘贴和移除。
- 同内容不同文件名的 hash 去重。
- 同一 artifact 被不同分支引用时的垃圾回收。
- OpenAI 兼容、Anthropic、Gemini 图片输入 fixture。
- 未知模型允许确认发送，参数和附件均未被目录规则删除。
- codec/profile 不支持文件块时显式失败。
- 重试、重启和导入导出后 artifact hash 一致。
- artifact 缺失、损坏和远端 ID 过期。
- 超大文件、伪造 MIME、恶意文件名和压缩包路径穿越。
- 取消上传后资源和临时文件清理。
- 长会话滚动时原图不被批量解码。

## 验收标准

- 用户发送的图片确实出现在捕获到的 Provider 请求中，而不只是 UI 卡片中。
- 重启应用并重新生成后，同一附件仍能按相同内容 hash 发送。
- 未知模型不会因为不在内置目录中失去附件入口。
- 缺失或不支持的附件会阻止请求并指出具体 message/block/artifact。
- 附件是否包含在导出和 RequestSnapshot 中由用户明确选择；认证字段的处理留给后续安全专题。
- 附件功能关闭或尚未进入 V1 时，不增加核心聊天常驻加载和网络行为。

详细安全边界见 [安全与隐私规范](../SECURITY_AND_PRIVACY.md)，上下文规则见 [对话上下文与工具连续性](../CONVERSATION_CONTEXT_AND_TOOLS.md)。
