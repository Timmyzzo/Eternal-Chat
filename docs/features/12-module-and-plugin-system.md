# 模块与插件系统

## 状态

- 里程碑：V2
- 当前状态：`deferred`
- 架构前置：MVP 需保留轻量 FeatureModule 注册边界，但不实现第三方插件运行时
- 依赖：稳定领域模型、动态 import、模块生命周期、模块 migration、性能与兼容性门禁

## 用户问题

Eternal Chat 需要逐步加入知识库、MCP、提示词、同步和语音等能力，又不能重演大型客户端所有功能常驻、依赖互相缠绕和关闭后仍占资源的问题。未来第三方扩展还需要明确权限和兼容边界，不能把任意代码直接放进核心 WebView。

## 目标

- 落实当前基线原则：核心只有聊天、连接/端点/模型管理和设置。
- 所有其他功能通过注册表、动态 import 和生命周期挂载。
- 模块关闭时不注册路由、按钮、订阅、后台任务和网络连接。
- 为内置模块提供稳定、可测试的 FeatureModule 契约。
- 在 V2 后续阶段提供权限受限、版本化的外部插件 API。
- 模块数据、消息块和迁移可保留、诊断和安全卸载。

## 非目标

- MVP 不提供第三方插件安装器、市场或兼容性承诺。
- 不允许直接安装任意 npm 包到应用运行目录。
- 不向 WebView 暴露通用 shell、任意文件系统或无限制网络权限。
- 不允许模块替换 ContextAssembler、删除未知消息块或改写核心工具语义。
- 不为单一功能建立重型 IoC 容器、全局事件总线或常驻调度器。
- 不承诺跨主版本永久兼容未冻结的内部 API。

## 两级扩展模型

### 内置 FeatureModule

随应用构建、由本项目维护的内置模块。它遵循当前 FeatureModule 注册思路，可以贡献：

- 懒加载路由。
- 设置页面或 schema。
- 聊天工具栏动作和右侧面板。
- 有命名空间的数据 migration。
- 生命周期钩子和受控后台任务。
- 有版本的消息块渲染器、工具定义或导入导出处理器。

提示词、附件、MCP、知识库和同步优先以这种方式落地。

### 外部插件

V2 中在内部模块契约稳定后设计。外部插件 API 必须比内部 React/TypeScript API 更窄，首个版本优先提供声明式 manifest、命令/数据能力和受控贡献点。未经独立 sandbox 与威胁评审，不允许外部插件把任意 React/JavaScript 直接注入核心 WebView。

外部 UI 扩展的具体隔离方式、签名和分发渠道需要单独 ADR；在它们确定前，只能完成 API/fixture 设计，不能把“能加载本地脚本”标记为插件系统完成。

## 内置模块契约

详细类型在实现阶段确定，但语义至少包括：

- `id`、版本、显示信息和最小应用版本。
- 默认是否启用，以及用户可否关闭。
- 动态入口，不在应用启动时执行模块主体。
- routes、settings、chat actions 等贡献声明。
- 所需权限和可选依赖。
- migration 版本和数据命名空间。
- `enable`、`disable`、`dispose` 的可等待生命周期。
- 健康状态、错误和诊断摘要。

注册表只能装配模块，不承载模块业务。模块之间通过稳定领域接口或显式 capability 交互，不直接导入对方内部 store 和组件。

## Manifest 与兼容性

外部插件 manifest 至少声明：

- 唯一 ID、版本、作者/来源和入口类型。
- 支持的应用版本与插件 API 版本。
- 请求的权限、网络域名、文件范围和 secret 槽位。
- 贡献点、依赖和可选依赖。
- 数据 schema/migration 版本。
- 完整性 hash 和未来签名信息。

manifest 和插件包均视为不可信。版本不兼容、权限未知、hash 不符或 migration 无法验证时保持禁用。不能为了“尽量加载”而忽略字段。

## 生命周期

1. 应用只加载内置的轻量 manifest/注册信息。
2. 根据设置决定是否启用模块。
3. 启用前验证依赖、版本、权限和 migration。
4. 动态加载模块入口并注册贡献。
5. 模块运行期间记录自己的任务、订阅、连接和资源所有权。
6. 禁用时先阻止新任务，再取消活动任务、卸载贡献、释放资源。
7. 卸载默认保留用户数据；删除数据是单独、可预览的破坏性操作。

`disable/dispose` 失败时模块进入错误状态，应用仍应移除可产生新副作用的入口并显示未清理资源，不能假装已完全关闭。

## 权限模型

权限使用最小能力声明，而不是一个“完全信任”开关。可能的能力包括：

- 读取模块自己的存储。
- 读取用户明确选择的文件或目录。
- 写入用户明确选择的位置。
- 访问指定网络域名。
- 注册模型可见工具。
- 使用通知、剪贴板或 opener。
- 请求属于本模块的认证绑定或值引用；实际凭据访问方式后续决定。
- 启动经过配置和确认的 MCP sidecar 类进程。

核心规则：

- 权限在首次启用和权限扩大时展示并确认。
- manifest 未声明的能力不可调用。
- 用户撤销权限后立即阻止新操作。
- 模型、工具输出和导入配置不能代替用户授予权限。
- 不提供通用 shell 和全磁盘隐式访问。
- Tauri capability 与应用内模块权限必须同时满足。

## 数据与 migration

- 每个模块拥有独立命名空间和 migration 序列。
- 模块 migration 由核心 migration coordinator 调用，但 SQL/语义由模块负责。
- migration 必须可重复验证、事务化并带 checksum。
- 模块禁用不回滚或删除数据。
- 模块卸载后数据可保留为 opaque namespace，重新安装兼容版本后恢复。
- 核心备份记录模块 ID、版本和数据 hash；缺少模块时不丢弃。
- 模块只能新增有版本的块类型，不能改变核心 `text/tool/reasoning/source` 语义。

## 历史与上下文兼容

模块关闭或缺失时，历史数据仍必须安全存在：

- UI 使用通用 fallback 展示块类型、来源、状态和不可用原因。
- ContextAssembler 遇到模块块时按注册的 serializer 或显式策略处理。
- 如果该块是下一轮必需证据而 serializer 不可用，阻止发送并指出依赖模块。
- 不能静默删除块、只发送助手 final text 或把未知 JSON 转成空字符串。
- 已保存的标准 tool result 即使 MCP/知识库模块关闭，仍可由核心 codec/profile 回放。
- 模块重新启用后必须读取同一版本数据，不创建重复历史。

## 贡献点边界

### 路由与设置

路由按模块前缀命名，关闭后不可访问。设置值按模块命名空间保存，不能覆盖核心 key。

### 聊天动作

动作只能通过公开命令接口读取当前会话的必要摘要，并返回明确操作；不能直接修改任意 store。涉及发送、文件、网络或删除时遵循相应权限和确认。

### 工具与消息块

模块注册工具定义和可选渲染器，但工具调用/结果仍进入核心 ToolExchange、RequestSnapshot 和 ContextManifest。模块不得建立只有自己知道的第二套上下文历史。

### 后台任务

每个任务必须有 owner module ID、取消句柄、状态和资源上限。核心可在禁用、退出和诊断时枚举并停止任务。

## UI

- 模块设置页使用紧凑列表显示名称、状态、版本、权限、资源状态和错误。
- 启用开关只表示期望状态；实际加载/失败状态单独显示。
- 权限变化以差异形式呈现，不用笼统“需要全部权限”。
- 禁用/卸载/删除数据是三个不同操作。
- 模块错误不能让整个设置页或聊天页崩溃。
- 外部插件明确显示来源、完整性、签名/未签名状态和风险。

## 性能预算

- 禁用模块：主体 bundle 不加载，零后台 timer、listener、worker、server 连接和文件扫描。
- 启用但空闲：必须有模块级内存和任务基线。
- 动态 import 失败不触发无限重试。
- 模块页面和大型依赖只在首次访问或功能触发时加载。
- 模块资源在 disable/dispose 后由泄漏测试证明回落，不只检查 UI 消失。
- 核心启动性能测试分别在“全部可选模块关闭”和“典型模块组合”下运行。

## 安全与供应链

- 内置模块依赖进入常规依赖审计和发布签名。
- 外部插件安装前验证 manifest、hash、版本和未来签名策略。
- 未签名开发插件只能在显式开发模式使用，并清楚标记风险。
- 插件更新的权限扩大、所有者变化或签名变化需要重新确认。
- 插件日志、诊断和错误遵循核心脱敏规则。
- 外部插件的凭据和认证访问不在当前 API 范围；恢复安全专题后再定义是否提供受控操作。
- 第一版不建立公共市场，避免把审核、撤回和恶意更新问题假装已经解决。

## 错误与恢复

- 依赖缺失/循环：保持相关模块禁用并显示依赖链。
- migration 失败：回滚该事务，模块进入只读/错误状态，不影响核心 schema。
- 加载异常：隔离错误并卸载已注册贡献。
- disable 超时：阻止新任务，报告残留 owner/resource。
- 插件 API 版本过新：不加载，不尝试猜测兼容。
- 历史块缺 serializer：保留原始 JSON，并阻止会破坏证据的请求。
- 插件包损坏或签名失败：隔离文件，不执行入口。

## 自动化测试

- 动态 import 只在启用/访问时发生。
- enable/disable/dispose 顺序、幂等和错误恢复。
- 路由、按钮、订阅、worker、timer、网络和进程所有权清理。
- 依赖排序、缺失依赖和循环检测。
- 权限首次授权、扩大、撤销和拒绝。
- 模块 migration 成功、失败回滚、checksum 和重装恢复。
- 未安装模块的数据备份/恢复和通用历史 fallback。
- 关键模块块缺 serializer 时显式阻断，不静默丢失。
- 标准 tool result 在模块关闭后仍可跨轮回放。
- manifest 畸形、路径穿越、hash/签名失败和不兼容版本。
- 全部模块关闭的启动、内存和网络基线。
- 反复启停模块的长时间泄漏测试。

## 验收标准

- 关闭所有可选模块后，核心聊天、Provider/模型管理和设置可独立构建与运行。
- 禁用模块不会加载主体代码、发起连接、扫描文件或留下 timer/listener。
- 模块无法静默改写、裁剪或绕过核心上下文和工具连续性规则。
- 模块缺失时历史数据可查看、可备份，关键证据不会被空值替代。
- 权限范围、数据删除和外部副作用在执行前对用户可见。
- 在没有安全隔离与兼容契约证据前，不把任意本地脚本加载能力称为“插件 API 已完成”。
