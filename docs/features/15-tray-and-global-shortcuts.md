# 托盘与全局快捷键

## 状态

- 里程碑：V1
- 当前状态：`deferred`
- 依赖：Tauri window/tray/global-shortcut/single-instance 能力、设置、流所有权、国际化

## 用户问题

桌面用户希望快速唤起应用、创建会话并控制窗口行为，但托盘和全局快捷键会影响进程是否退出、流式请求是否继续以及系统级按键冲突。行为不明确时，用户会误以为应用已关闭，实际却仍在后台占用内存或网络。

## 目标

- 提供可关闭、状态明确的托盘入口。
- 提供少量、用户可配置的全局快捷键。
- 明确定义关闭窗口、隐藏到托盘、退出和 active stream 的关系。
- 与 single-instance 和 window-state 协同，不创建重复窗口或重复监听。
- 托盘菜单、通知和快捷键状态支持本地化与无障碍。
- 禁用相关能力后释放系统注册和后台资源。

## 非目标

- V1 不做常驻后台 agent、定时任务中心或菜单栏聊天机器人。
- 不默认开机启动；是否加入开机启动需单独确认平台方案和权限。
- 不注册大量全局快捷键或覆盖常见系统组合键。
- 不在系统通知中默认显示敏感 prompt、回答或文件名。
- 不因窗口隐藏而改变消息上下文、Provider 或参数。

## 最小托盘菜单

- 显示/隐藏 Eternal Chat。
- 新建会话并聚焦输入框。
- active request 存在时显示状态，并可选择回到该会话；是否提供停止命令需复用同一确认/取消语义。
- 设置。
- 退出应用。

菜单项根据状态启用/禁用，不用轮询复制整份聊天状态。托盘图标可表达普通/生成中/错误等少量状态，但不能只靠颜色传达关键含义。

## 窗口关闭与退出

设置提供明确选择：

- 关闭窗口即退出应用。
- 关闭窗口隐藏到托盘。

默认值在 V1 实现前结合平台惯例确定，并在首次启用托盘时说明。无论采用哪种默认值，行为必须可见且可修改。

### Active stream

- 隐藏到托盘时，若设置允许后台继续，流保持并由 conversation/request ID 隔离。
- 用户选择退出且存在 active stream 时，显示“取消并退出/返回应用”等明确选择。
- 强制系统退出或崩溃时，启动恢复规则把 pending/waiting_retry/streaming 标为 interrupted。
- 退出流程等待有界的持久化和资源清理，超时后记录可恢复状态，不无限挂起。

## 全局快捷键

首个 V1 增量只要求：

- 显示并聚焦主窗口。
- 新建会话并聚焦输入框。

是否增加其他命令必须有明确用户价值和冲突测试。应用内快捷键与全局快捷键分开配置；全局快捷键只在用户启用时注册。

规则：

- 录制组合键时显示规范化结果和平台冲突。
- 注册失败保留用户设置但标记未生效，不静默改用其他组合。
- 不允许只有单个普通字母/数字等高误触组合。
- 快捷键触发时不读取剪贴板、不自动发送消息、不向模型发请求。
- 同一命令的重复事件去抖，single-instance 场景只由主进程实例处理。

## Single-instance 与窗口状态

- 第二实例启动时把参数交给主实例并退出，不创建第二套数据库连接、tray 或 shortcut。
- 主实例恢复窗口、取消最小化并聚焦；如果正在全屏或有 modal，遵循平台安全焦点规则。
- 窗口位置和尺寸使用当前技术选型中的 window-state 能力保存。
- 显示器被移除、缩放变化或坐标失效时把窗口恢复到当前可见工作区。
- 不保存会导致内容小于 UI 最小尺寸的状态。

## 通知

通知不是托盘的强制前置，但使用同一桌面集成边界：

- 默认只显示“回答完成”“请求失败”等低敏状态。
- 显示回答预览必须由用户单独启用。
- 点击通知打开对应会话和消息。
- 同一请求只产生一个终态通知。
- 应用当前前台可见时默认不发送冗余系统通知。

## UI 与设置

- 设置页显示托盘启用状态、关闭窗口行为和全局快捷键。
- 每个快捷键有录制、清除、恢复默认和冲突状态。
- 平台不支持某能力时显示不可用原因，不保留假开关。
- 退出操作与“隐藏”使用不同文案和图标。
- 托盘菜单更新使用局部状态，不依赖渲染整棵 React 应用。

## 隐私与安全

- Tauri capability 只授予需要的 tray、window、single-instance、notification 和 global-shortcut 权限。
- 禁用全局快捷键后立即 unregister。
- 快捷键和托盘事件只能触发内部 allowlist command。
- 通知默认不包含消息正文、source、文件名、模型 reasoning 或 tool result。
- 窗口标题和托盘 tooltip 避免默认暴露当前会话标题的敏感内容。
- 日志记录命令 ID 和结果，不记录用户输入或剪贴板。

## 错误与恢复

- tray 创建失败：应用仍以普通窗口模式运行并显示设置状态。
- shortcut 被系统/其他应用占用：显示冲突，不自动替换。
- window-state 损坏：回退到安全默认尺寸和可见位置。
- 第二实例消息失败：不得启动独立业务运行时；显示平台级错误并退出。
- 退出清理超时：保留 interrupted 恢复证据，避免数据库处于永久 streaming。
- 平台通知权限被拒：保持功能关闭，不反复弹权限请求。

## 性能

- 托盘和快捷键监听只注册一次。
- 隐藏窗口不意味着无限保留已离开会话的大型 UI cache；按性能规范释放非必要资源。
- 后台继续流式时只保持必要 transport、parser 和持久化状态。
- 反复显示/隐藏不能重复创建 React root、数据库连接、tray、timer 或 Channel listener。
- V1 长时间测试包含 100 次显示/隐藏、快捷键触发和窗口关闭恢复。

## 自动化与平台测试

- close-to-exit 和 close-to-tray 两种设置。
- active stream 下隐藏、恢复、退出、取消和崩溃恢复。
- shortcut 注册、冲突、清除、重启恢复和禁用释放。
- second instance 聚焦主窗口且不重复初始化资源。
- 多显示器拔插、DPI 变化和不可见窗口恢复。
- tray 菜单状态、国际化和 active request 定位。
- 通知隐私默认值、点击定位和单终态去重。
- Windows 必测；macOS/Linux 按发布支持矩阵做真实平台冒烟，不能只用 mock 宣称支持。
- 反复显示/隐藏和启停快捷键的 listener/内存泄漏测试。

## 验收标准

- 用户能明确区分隐藏窗口与退出应用，并控制 active stream 的结果。
- 全局快捷键只在用户启用且注册成功时生效，冲突不会被静默替换。
- 第二实例不会产生第二套数据库、tray、shortcut 或流式运行时。
- 默认通知和系统表面不泄露会话正文或工具资料。
- 禁用托盘/快捷键后相关监听和系统注册被释放。
- 100 次显示/隐藏和快捷键触发后，内存与 listener 数量不持续增长。

平台权限和资源清理要求见 [安全与隐私规范](../SECURITY_AND_PRIVACY.md) 与 [性能预算](../PERFORMANCE_BUDGET.md)。
