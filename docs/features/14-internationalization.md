# 国际化与本地化

## 状态

- 里程碑：V1
- 当前状态：`deferred`
- 依赖：UI 文案清单、模块命名空间、设置持久化、日期/数字格式化、无障碍测试

## 用户问题

国际化不只是翻译菜单。模型名称、错误、时间、数字、快捷键、动态参数和用户内容都需要明确哪些应翻译、哪些必须保持原文。若在界面完成后才处理字符串拼接和布局，容易造成大量返工和中文/英文显示不一致。

## 目标

- 建立有类型或可静态检查的消息目录和稳定 message key。
- V1 至少用简体中文与英文完整验证国际化机制。
- 用户可选择语言或跟随系统，重启后保持。
- 日期、时间、数字、费用、复数和排序按 locale 处理。
- 核心与可选模块使用独立、懒加载的翻译命名空间。
- 错误保留稳定代码与 Provider 原文，同时提供客户端本地化说明。

## 非目标

- 不翻译用户消息、模型回答、工具结果、文件正文或 Provider/模型 ID。
- 不把机器翻译运行时服务作为 UI 文案的默认来源。
- V1 不承诺所有语言、所有 RTL 布局和地区法规都已覆盖。
- 不允许翻译文本改变请求参数、JSON key、数据库枚举或协议字段。
- 不因语言变化重新生成会话标题或模型内容。

## 语言范围

首个 V1 验收至少覆盖：

- `zh-CN`：主要中文界面、中文排版和常见 Windows 字体。
- `en-US`：验证英文长度、复数、日期和数字格式。
- 伪本地化 locale：测试文本膨胀、缺 key 和硬编码字符串。

更多语言在翻译资源和人工 QA 到位后加入。未完成语言不得只因存在少量条目就显示为可选。

## 文案分类

### 必须本地化

- 导航、按钮、表单标签、空状态、确认和设置说明。
- 客户端生成的错误摘要、状态、权限和隐私提示。
- 内置参数的显示名与帮助文本。
- 日期范围、数量单位、费用标签和无障碍名称。
- 托盘菜单、通知和更新界面。

### 保持原文

- Provider/模型 ID、endpoint、Header/JSON 字段和错误代码。
- 用户输入、模型输出、reasoning、tool result、source title 和文件内容。
- 用户自定义 Provider、模型、提示词、助手和知识库名称。
- 外部 server/tool 的原始名称；可另有本地显示别名，但不能替换协议名。

## 消息目录规则

- 使用稳定语义 key，不用完整英文句子作为 key。
- 不在 React 组件中拼接可翻译句子。
- 变量使用命名占位符并进行类型/存在性检查。
- 复数、选择和日期范围使用国际化格式能力，不手写中文/英文条件分支散落全局。
- 允许富文本时只接受有限的命名片段，不把翻译字符串当 HTML。
- 缺 key 在开发和测试中报错；生产回退到已配置 fallback locale，并记录不含私人数据的诊断。

具体 i18n 库在 V1 开始前用 TypeScript 类型支持、按 namespace 懒加载、ICU/复数能力和 bundle 体积进行小型 ADR 选择，不反向改变上述行为。

## Locale 选择与持久化

优先级：

1. 用户显式选择。
2. 支持的系统 locale。
3. 产品默认 locale。

切换语言应即时更新应用 UI、托盘菜单和后续通知，不刷新或重建会话。用户内容的语言、system prompt 和模型参数不随 UI locale 自动改变。

## 日期、数字与排序

- 数据库存储 UTC 时间戳；显示时按系统时区和 locale 格式化。
- 相对时间必须能展开查看绝对时间。
- token、字节、持续时间和费用使用 locale 数字格式，但导出机器格式保持稳定。
- 多币种保留币种代码，不能只显示符号导致歧义。
- 搜索和列表排序不得仅依赖 UI 翻译文本；Provider/模型 ID 使用稳定字段。
- 中文、英文混排保持 0 letter spacing，遵循既有字体和行高规范。

## 错误与外部内容

错误对象保留：

- 稳定客户端错误代码。
- 本地化用户说明。
- Provider 原始错误代码和脱敏原文。
- 可重试和建议操作。

翻译不能把 Provider 的具体错误改写成错误事实。未知错误显示通用本地说明和可展开原文。外部 Markdown、tool description 和 source title 不进入翻译目录。

## 模块与插件

- 每个内置模块拥有独立翻译 namespace，模块禁用时不加载资源。
- 模块必须声明所支持 locale，并提供 fallback。
- 外部插件不能覆盖核心 message key。
- 插件翻译资源按不可信 JSON 校验大小和结构，不能包含可执行 HTML/脚本。
- 缺失插件翻译时显示插件提供的 fallback 文本或稳定 ID，不让页面崩溃。

## UI 与布局

- 控件使用响应式约束、换行、截断和 tooltip，不能为某个语言写固定文本宽度。
- 图标按钮仍有本地化 `aria-label` 和 tooltip。
- Dialog、菜单和 segmented control 用最长目标语言测试。
- 不用 viewport 宽度缩放字号解决翻译溢出。
- 输入法组合态不能触发发送或快捷键误操作。
- 初始 V1 若未完成 RTL，不宣称支持；布局代码避免不必要的 left/right 硬编码，为后续 logical properties 留出空间。

## 导入导出

- 机器可读导出使用稳定字段和 ISO 时间，不随 locale 改 schema。
- 面向用户的可读标题可本地化，但必须与稳定字段分离。
- 导入不依赖导出时的 UI 语言。
- 提示词、助手和设置中的用户文本保持原文。

## 自动化测试

- locale 选择、系统回退、重启持久化和即时切换。
- message key 完整性、未使用 key 报告和 namespace 懒加载。
- 中英文复数、日期、时区、数字、字节、持续时间和货币。
- Provider 原文、模型 ID、JSON key 和用户内容不被翻译。
- 伪本地化下导航、表单、按钮、表格、Dialog 和小窗口无溢出。
- 中文/英文输入法组合态与 Enter 发送。
- 模块禁用时翻译资源不加载。
- 外部插件缺翻译、畸形资源和 key 冲突。
- 键盘、读屏和 focus 文案在两个 locale 下通过。

## 验收标准

- 核心 MVP 与 V1 页面在 `zh-CN`、`en-US` 下没有明显硬编码混杂和不可用布局。
- 切换 UI 语言不会修改会话、提示词、模型请求或历史内容。
- Provider 错误同时保留可靠原文/代码和本地化说明。
- 可选模块关闭时不加载其翻译 bundle。
- 新增用户可见文案时，静态检查或测试能发现缺少 message key。
- 伪本地化和小窗口测试不会出现文本遮挡、按钮不可操作或内容越界。

界面与无障碍要求见 [UI/UX 规格](../UI_UX_SPEC.md)。
