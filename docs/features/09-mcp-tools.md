# MCP 工具

## 状态

- 里程碑：V2
- 当前状态：`deferred`
- 依赖：已验证的工具连续性、模块注册、权限系统、artifact、流式状态机

## 用户问题

MCP 可以把文件、搜索、数据库和业务系统接入模型，但它同时放大了两个风险：工具可能获得超出预期的本机或网络权限，工具结果也可能只在调用当轮可见而在下一轮消失。Eternal Chat 只有在核心工具交换已经通过线协议 canary 后才能加入 MCP。

## 目标

- 以可关闭模块连接和管理 MCP server。
- 发现工具及其输入 schema，并让用户按 server/tool 控制权限。
- 展示工具调用、参数、确认、执行、结果、错误和耗时。
- 把 MCP 结果保存为规范 tool exchange，并在后续轮次可靠回放。
- 对取消、超时、断线、重复调用和大型结果给出明确策略。
- MCP 凭据的保存、注入和导出规则在该 V2 模块进入实现前由安全专题决定，当前不锁定方案。

## 非目标

- MCP 不进入 MVP 或 V1，也不是核心聊天的依赖。
- 首个 MCP 增量只要求 tools；prompts、resources、sampling 和其他能力分别评审后加入。
- 不提供任意 shell 命令输入框或通用脚本执行器。
- 不默认自动批准有副作用的工具。
- 不建立隐藏的无限 agent/tool loop。
- 不把 MCP 输出只保存成 UI 卡片或助手摘要。

## 启用前置条件

开始实现本功能前必须已有证据证明：

- 核心 canonical tool call/result 数据模型稳定。
- OpenAI、Anthropic 和 Gemini 的跨轮 canary 均通过。
- ContextAssembler 不依赖 UI 当前加载窗口。
- 大型 tool result 有 `modelContent`、`rawRef` 和可见超限策略。
- 模块关闭时可以取消任务并卸载监听。

任何一项不满足，MCP 开发应停留在设计和 fixture 阶段。

## 传输范围

### 远程 server

首选 MCP 当前标准远程传输，并按协议版本进行能力协商。为兼容旧 server 可按明确配置支持 legacy transport，但不能通过猜测自动切换并掩盖错误。

### 本地 server

本地 stdio 的权限和生命周期在该 V2 模块进入实现时单独设计。平台层预期只暴露面向 MCP server 的窄接口，包括启动已配置可执行文件、参数、环境值引用、stdin/stdout、取消和退出状态。MCP 协议、工具 schema 和上下文语义仍留在 TypeScript 模块。

## Server 配置

每个 server 至少记录：

- 稳定 ID、名称、传输类型和启用状态。
- 远程 endpoint 或经验证的本地可执行描述。
- 协议版本与能力协商结果。
- 超时、重连和并发限制。
- 认证绑定及其配置状态；具体凭据存储形态尚未决定。
- 工具 allowlist、确认策略和最后一次发现的 schema hash。
- 来源、更新时间和最后一次健康检查结果。

导入配置时默认禁用 server，要求用户审阅 endpoint、可执行文件、环境变量和权限后再启用。

## 工具发现与身份

- 工具名称在本地以 `serverId + remoteName` 形成稳定命名空间，避免不同 server 冲突。
- 保存工具描述、输入 schema、能力元数据和 schema hash 的快照。
- server 更新 schema 时，在下一次调用前显示变化；已授权的高风险工具不能自动沿用扩大后的权限。
- 工具描述来自不可信 server，不能作为客户端系统指令执行。
- 模型请求只包含当前会话明确允许的工具集合。

## 调用流程

1. Provider 返回带稳定 call ID 的 tool call。
2. codec/reducer 将调用保存为 `pending`，并校验工具名称和 JSON 参数。
3. 权限策略决定直接执行、请求用户确认或拒绝。
4. 用户确认界面显示 server、工具、参数、潜在数据范围和副作用。
5. MCP client 执行调用，支持取消和超时。
6. 原始结果按需保存为 artifact；同时生成明确的 `result.modelContent`。
7. 工具状态、结果、耗时和错误先持久化，再继续当前轮 Provider 请求。
8. 完成后的 tool exchange 进入当前分支历史，后续用户轮次由 ContextAssembler 重新序列化。

继续模型生成属于新的可审计请求步骤，应有独立 RequestSnapshot，并与原始 call ID 关联。不得在内存中完成多次工具循环却只保存最终答案。

## 权限与确认

权限至少按以下维度表达：

- server 是否启用。
- 工具是否允许暴露给模型。
- 每次确认、会话内允许或总是拒绝。
- 文件读取/写入范围。
- 允许访问的网络域名或服务。
- 是否可能修改、发送或删除外部数据。
- 是否会向第三方发送会话、附件或知识库内容。

“本次允许”不得升级为永久允许。工具或 schema 变化后重新确认。无法可靠判断副作用时默认请求确认。

## 结果与上下文连续性

- `result.modelContent` 是后续 Provider 回放的权威内容。
- 原始 MCP content、附件或大型结构可以保存到 `rawRef`，但不能只保存 rawRef 而没有模型可见结果。
- 文本、结构化 JSON、图片和嵌入资源应保持类型；不应一律压成自然语言摘要。
- 失败、拒绝、取消和超时也形成有状态的 tool result，按 Provider 协议显式返回。
- 工具结果过大时不得随机截断。允许工具分页、用户选择范围或显式派生摘要，并记录来源范围。
- UI 展示、SQLite 块和下一轮线协议必须能通过同一 tool call ID 关联。

本功能的 P0 canary 必须验证：第一轮 MCP 工具返回只存在于结果中的随机值，助手最终文本不复述该值；第二轮实际请求仍包含相同 call ID 和 `modelContent`。

## 提示注入与不可信输出

- MCP server、工具描述、参数 schema 和结果均视为不可信外部数据。
- 工具结果在上下文中使用明确的 tool 角色/块边界，不拼接进 system prompt。
- UI 区分“工具返回内容”和“客户端说明”，不把结果中的指令当成安全建议。
- 文件、URL、HTML、Markdown 和错误消息遵循现有安全渲染规则。
- 用户仍应看到模型计划发送给外部工具的敏感参数；隐藏字段只用于 secret 引用，模型不能生成或读取 secret 值。

## 运行限制

- 每轮最大工具步骤、并发数、单次超时和总时长必须有配置与硬上限。
- 达到限制时暂停并显示当前状态，不自动扩大预算。
- 同一 call ID 的重复事件必须幂等处理，不能重复执行有副作用的工具。
- 取消会终止等待中的调用，并尽力停止本地进程或远程请求；无法确认远端是否已执行时显示“结果未知”。
- server 断线后的重连不能自动重放非幂等调用。

## UI

- MCP 设置页显示 server 状态、传输、工具数量、权限、健康检查和最近错误。
- 会话工具选择器只显示已启用且允许的工具。
- 工具调用块展示参数、确认状态、执行状态、模型可见结果、原始结果入口和耗时。
- 多工具并行时按 call ID 稳定更新，不因事件到达顺序改变历史顺序。
- 关闭 MCP 模块后入口消失；历史工具块仍以只读通用形式可查看。

## 数据与迁移

V2 migration 应为 server 配置、工具快照和权限记录提供独立命名空间。MCP 调用本身继续使用核心 MessageBlock/ToolExchange，不建立与核心上下文脱节的第二套聊天历史。

模块卸载默认保留配置和历史数据。删除 server 时分别确认配置和工具缓存范围；凭据清理由后续安全方案定义，历史消息中的工具交换不得被连带破坏。

## 错误与恢复

- server 无法启动/连接：显示 transport、退出码或脱敏网络错误。
- 协议协商失败：不猜测工具列表。
- schema 无效：不暴露该工具给模型。
- 参数不匹配：阻止执行并保存失败状态。
- 用户拒绝：向模型返回明确拒绝结果，不伪装网络失败。
- 工具结果落库失败：不得继续模型生成并标记成功。
- 应用崩溃：启动后把执行中调用标为 `interrupted/unknown`，不得自动重放。
- server 被禁用：取消新调用；历史仍可查看和回放已持久化 `modelContent`。

## 性能

- 模块禁用时不连接 server、不发现工具、不注册 timer/listener。
- 工具发现按需执行并缓存 schema hash。
- 大结果流式写 artifact，避免在 Zustand 中长期保存多份完整副本。
- 工具列表和结果详情按需加载。
- 本地 server 进程必须有所有权记录，关闭会话、禁用模块和退出应用时清理。

## 自动化测试

- 远程 transport 握手、发现、调用、取消、超时和重连 fixture。
- 本地 transport 若实现，覆盖参数转义、进程退出、环境 secret 隔离和资源清理。
- 重名工具命名空间与 schema 变化重新授权。
- 参数校验、拒绝、失败、取消和未知结果类型。
- call ID 幂等，断线后不重放非幂等调用。
- 多工具并行、乱序事件和继续生成的 RequestSnapshot 链。
- MCP 跨轮 canary 捕获实际 Provider 请求。
- 大结果分页/显式摘要，不发生隐藏截断。
- secret 不进入 JS、SQLite、日志、诊断和导出。
- 恶意描述、Markdown、URL、文件名和 prompt injection fixture。
- 模块关闭后无连接、后台任务或新增内存增长。

## 验收标准

- 用户可以准确看到哪个 server 的哪个工具以什么参数执行，并决定是否授权。
- 工具成功、失败、拒绝、取消和未知终态都被持久化且可恢复。
- 下一轮请求包含历史 MCP tool result 或经过验证的 Provider anchor，不允许 final-text-only。
- 工具结果不因 UI 折叠、分页、重启或模块关闭而从规范历史消失。
- MCP 凭据和本地执行权限不暴露给模型或普通前端状态。
- 禁用 MCP 后，核心聊天的启动时间、常驻连接和内存不包含 MCP 成本。
