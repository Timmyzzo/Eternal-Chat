# 备份与同步

## 状态

- 里程碑：MVP / V2
- 当前状态：MVP 导入导出与本地备份为 `specified`；WebDAV 同步为 `deferred`
- 依赖：schema migration、artifact manifest、模块注册、版本化导入导出格式

## 用户问题

本地优先不能等于数据只能留在一台机器。用户需要可靠导出、备份和恢复会话；跨设备同步还必须避免静默覆盖和损坏扩散。

## 范围拆分

### MVP：导入导出与本地备份

- 导出单会话为可读 JSON。
- 导出全部数据为带版本 manifest 的备份包。
- 可选包含 artifact；明确显示范围和大小。
- 导入前完整校验，在临时区解析后事务提交。
- 支持恢复到空库，也支持以新 ID 合并到现有库。

### V2：WebDAV 同步模块

- 用户主动配置的 WebDAV 远端。
- 客户端加密的版本化备份快照上传和下载。
- 多设备代次与冲突检测，不做静默 last-write-wins。
- 可配置手动或低频计划同步，关闭后没有后台网络。

首个 V2 同步增量采用“加密快照同步”，不做逐消息实时多主合并。这个范围更容易证明恢复正确性，也不把复杂同步状态机引入核心聊天。

## 非目标

- MVP 不连接任何云服务。
- V2 首个增量不做实时协作、多人共享或后台账号体系。
- 不把远端最新时间戳直接当成覆盖依据。
- 不让备份/同步模块改变 ContextAssembler 的消息语义。
- 凭据、加密、敏感字段排除和远端隐私承诺属于后续安全专题，当前 MVP 不以这些结论作为门禁。

## MVP 导出格式

### 单会话 JSON

用于人工查看和迁移，至少包含：

- 格式版本和导出应用版本。
- 会话元数据、当前 active leaf 和全部相关分支。
- Message、结构化 blocks、tool call/result、source/citation。
- RequestSnapshot、RequestAttempt 和 ContextManifest 的可选部分。
- artifact manifest；用户选择不含文件时保留明确缺失标记。

### 全量备份包

备份包使用单一有版本的容器，包含 manifest、结构化 JSON 数据和可选 artifact。manifest 至少记录文件路径、字节数、内容 hash、数据范围、schema/format 版本、创建时间和应用版本。

具体压缩实现可在编码前选择。不能把运行中的 SQLite 文件简单复制后假定得到一致备份；应使用 SQLite 一致性备份机制或从事务快照导出。

## 导出流程

1. 用户选择单会话或全部数据。
2. UI 列出将包含的会话、消息、附件、知识库/模块数据和预计大小。
3. 用户选择是否包含连接/端点/profile 配置、请求快照、原始 trace 和 artifact。
4. 创建一致性读取快照并生成 manifest。
5. 写入用户选择位置的临时文件，完成后校验 hash。
6. 原子重命名为最终文件；失败时清理临时文件并保留本地数据库不变。
7. 显示导出位置、范围、hash 和完成状态。

## 导入与恢复流程

1. 用户选择备份文件。
2. 客户端在应用专用临时目录解包，不写入正式数据目录。
3. 校验容器版本、manifest、路径、大小、文件数、hash 和 JSON schema。
4. 生成导入预览：新增、冲突、缺失 artifact、不兼容模块和待迁移版本。
5. 用户选择恢复到空库、以新 ID 合并，或取消。
6. 在数据库事务中导入结构化数据，再原子移动 artifact。
7. 运行完整性检查，成功后提交；失败则回滚并报告临时文件清理状态。

不得把导入包中的绝对 ID 冲突静默覆盖到本地记录。合并时必须维护 parent、tool call、source、snapshot、attempt 和 artifact 引用映射；attempt 的 body hash 必须仍指向其父 snapshot。

## WebDAV 同步模型

### 配置

- endpoint、远端目录、用户名和连接策略。
- 连接测试只做最小读写探测并清理测试对象。
- 密码/token 的保存、TLS 策略和认证注入等安全问题在 V2 实现前另行设计；当前不锁定 keyring 或其他方案。

### 内容保护（延期）

是否加密快照、如何管理密码/token、远端对象暴露哪些元数据，以及备份是否排除认证字段，全部属于 [安全与隐私专题](../SECURITY_AND_PRIVACY.md)。该专题恢复前，WebDAV 仍保持 `deferred`，本文只冻结代次、冲突和恢复语义。

### 代次与冲突

每个快照记录稳定设备 ID、parent generation、创建时间、内容 hash 和应用/格式版本。

- 远端 generation 是本地已知 generation 的后继时，可以下载并进入恢复/合并流程。
- 本地与远端都从同一 parent 产生新 generation 时标记冲突。
- 冲突时保留两份快照，显示设备、时间、范围和差异摘要，由用户选择恢复或分别导入。
- 不使用设备时钟单独决定胜负。
- 上传采用临时对象和原子 MOVE/重命名能力；远端不支持时使用完成标记，避免半包被识别为有效快照。

## 模块数据

- 核心备份格式允许模块注册有版本的数据导出器和恢复器。
- 未启用模块的数据可以保留为 opaque、有 hash 的命名空间，但不能被核心错误解释。
- 导入缺少对应模块时显示“数据已保留、当前不可用”。
- 模块导出失败时整个备份不得标记完整成功；用户可明确选择排除该模块后重新导出。
- 知识库原文件、解析文本和向量索引分别选择；向量属于可重建派生数据，默认可不备份。

## UI

- 数据设置页提供单会话导出、全量备份、导入和完整性检查。
- 每次操作显示范围、预计大小、进度、取消、最终文件和错误。
- WebDAV 作为独立可关闭模块页面，显示最后成功、当前 generation、远端状态、下次计划和冲突。
- 破坏性恢复必须二次确认，并在开始前建议创建当前本地备份。
- 错误使用稳定状态，不用一次性 toast 隐藏重要恢复信息。

## 安全专题延期边界

- MVP 导出 UI 必须清楚列出将包含的数据范围，但不在本阶段制定敏感字段策略。
- WebDAV 的凭据、加密、远端隐私、权限和删除策略不作为当前 MVP 门禁。
- 自动同步、远端删除和内容保护只有在安全专题恢复并形成独立 ADR 后才进入实现。

## 错误与恢复

- 导出磁盘空间不足：停止、清理临时文件，不损坏源数据。
- 备份包 hash 不符：拒绝导入，不尝试“尽量读取”后静默缺数据。
- schema 过新：进入只读预览或提示升级，不能降级解析未知块。
- 导入中断：事务回滚，移动到正式目录的 artifact 有恢复清单。
- WebDAV 上传中断：保留本地快照，远端临时对象不作为有效 generation。
- 冲突：暂停自动应用，保留双方快照。
- 模块关闭：停止计划任务和网络请求，但不删除本地或远端快照。

## 性能

- 导入导出使用流式 I/O 和有界 buffer。
- 进度更新节流，不能为每个小文件触发全局 React 重渲染。
- artifact 通过内容 hash 避免在同一包内重复。
- 同步任务优先级低于用户主动聊天请求，并可暂停。
- V2 初版不为“增量同步”提前建立复杂 change log；只有在快照性能数据证明必要后再设计。

## 自动化测试

- 单会话 JSON 和全量包 round trip。
- 包含文本、思考、工具、来源、分支、附件和 interrupted 状态的 fixture hash 一致。
- 一致性快照期间并发写入的边界。
- ID 冲突映射和 parent/tool/source 引用完整。
- manifest/hash 不一致、损坏 JSON、缺失 artifact、schema 向前迁移、过新版本拒绝和未知块保留。
- WebDAV 临时上传、完成标记、超时、重试和取消 fixture。
- 双设备 generation 分叉与冲突保留。
- 模块数据缺失、排除和未安装模块恢复。
- 同步模块关闭后无 timer、网络和内存增长。

## 验收标准

- 从备份恢复后，核心 fixture 的消息、分支、tool result、source、snapshot、attempt 和 artifact hash 保持一致。
- 导入损坏包不会部分覆盖正式数据库。
- 多设备冲突不会被时间戳或最后上传者静默覆盖。
- 关闭同步模块后没有后台请求；MVP 本地导入导出仍可独立使用。
- WebDAV 在凭据、加密和远端隐私尚未重新设计前保持 `deferred`。

详细数据规则见 [数据模型](../DATA_MODEL.md)；安全范围见当前 `deferred` 的 [安全与隐私专题](../SECURITY_AND_PRIVACY.md)。
