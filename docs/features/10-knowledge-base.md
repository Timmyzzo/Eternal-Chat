# 知识库

## 状态

- 里程碑：V2
- 当前状态：`deferred`
- 依赖：模块注册、artifact、SQLite migration、sqlite-vec、embedding 配置、工具连续性

## 用户问题

用户需要让模型基于自己的长期资料回答，并能检查答案究竟来自哪个文件、哪个版本和哪个片段。知识库如果在后台静默注入不明摘要，或者检索结果没有进入后续上下文，会重复用户最关心的“界面看起来有资料，模型实际没拿到”的问题。

## 目标

- 建立本地优先、可关闭的知识库模块。
- 使用 SQLite 元数据与 `sqlite-vec + embedding` 完成向量检索。
- 资料导入、解析、切块、embedding 和索引过程可查看、暂停和恢复。
- 每次检索保存查询、命中文档版本、片段、分数、引用和模型可见内容。
- 检索结果以规范工具交换进入请求，并可在后续轮次继续回放。
- 用户明确控制哪些知识库参与当前会话和当前请求。

## 非目标

- 知识库不进入 MVP/V1，也不是核心聊天发送路径的依赖。
- 首个增量不做知识图谱、自动网页爬取、团队协作或云端管理后台。
- 不默认扫描用户目录或监控整个文件系统。
- 不把所有资料全文无条件塞入上下文。
- 不承诺第一版解析全部 PDF、Office、网页、音视频格式。
- 不把 embedding 模型目录当作能力白名单。

## 首个增量范围

为控制复杂度，首个可验证增量只要求：

- 创建、重命名和删除知识库。
- 导入 UTF-8 纯文本与 Markdown 文件。
- 内容哈希、版本、解析文本、切块和索引。
- 配置一个 embedding Provider/模型并完成维度校验。
- 对当前问题执行 top-k 检索。
- 在发送前查看命中片段，并作为 tool result 进入模型请求。
- 引用返回源文件、版本和片段位置。

PDF、Office、HTML 等解析器作为后续独立增量。新增格式前必须确定解析库、安全边界、位置映射和 fixture，不能只按扩展名读取。

## 用户流程

### 建库与导入

1. 用户创建知识库并选择 embedding 配置。
2. 用户明确选择文件或拖放到知识库页面。
3. 客户端复制内容到 artifact 存储，计算 hash 并创建文档版本。
4. 后台解析、标准化、切块、embedding 和写入索引。
5. UI 显示每个文件的阶段、片段数、失败原因和最后索引时间。
6. 失败文件可单独重试，不回滚其他已完成文件。

### 会话检索

1. 用户在会话中选择一个或多个已就绪知识库。
2. 发送前客户端用当前问题生成检索查询；首个增量只使用明确、可预览的查询，不做隐藏多轮改写。
3. 检索返回带文档版本和位置的候选片段。
4. 用户可查看、排除或调整数量；自动模式也必须显示本轮实际纳入项。
5. 客户端把检索记录保存为 `knowledge_search` tool exchange。
6. Provider 请求包含 `result.modelContent`，正文引用关联具体 source/citation。
7. 后续轮次需要这些资料时，ContextAssembler 按当前分支回放已纳入的检索结果。

## 数据模型

V2 migration 至少需要以下语义实体，物理表名在实现前与总数据模型统一：

- `knowledge_collection`：名称、状态、默认检索配置。
- `knowledge_document`：稳定文档 ID、显示名、来源类型和当前版本。
- `knowledge_document_version`：artifact ref、content hash、解析器版本、状态和错误。
- `knowledge_chunk`：版本、顺序、文本、位置范围、token 估算和 chunk hash。
- `knowledge_embedding`：chunk、embedding 配置 ID、维度、向量索引引用和创建时间。
- `knowledge_retrieval`：查询、配置、候选、最终纳入项、分数和 request/tool call 关联。

原始文件、解析文本过大内容和可选诊断放入 artifact；SQLite 保留可查询元数据。索引是可重建派生数据，文档版本和 chunk 文本才是权威来源。

## 切块与索引规则

- 同一文档版本使用固定 parser/chunker 版本，结果可重复。
- chunk 保留足够的来源位置，如行号、标题路径或未来 PDF 页码。
- 更新文件创建新版本，不原地改写旧版本，保证历史引用可解释。
- embedding 配置至少包含 Provider、模型 ID、维度和规范化方式。
- 不同维度或不兼容模型的向量不能写入同一索引分区。
- 更换 embedding 配置会建立新索引或显式重建，不静默混用旧向量。
- 内容 hash 相同的文档可以复用解析结果，但不同知识库的成员关系独立。

具体 chunk 大小、重叠和 top-k 是可配置默认值，应通过检索 fixture 和性能测试确定，不在文档阶段伪造唯一最佳数字。

## Embedding Provider

- 可以使用本地或远程 embedding；UI 必须显示文件内容是否会离开本机。
- 远程 embedding 端点使用可编辑认证绑定；凭据如何持久化由后续安全专题决定。
- 用户可手工添加未知 embedding 模型、维度和请求参数。
- Provider 错误不触发无提示模型替换。
- 发送批次、速率限制和重试必须可取消，并避免重复写入。
- RequestSnapshot/索引作业记录脱敏配置、模型 ID 和失败状态。

## 检索真实性与上下文

- 知识库选择不等于把全库注入上下文。
- 每次请求必须保存“查询了什么、候选是什么、最终纳入什么”。
- `result.modelContent` 包含实际发送给模型的片段、稳定 source ID 和位置。
- 原始检索候选可作为审计数据保存，但不能与模型实际看到的片段混淆。
- UI 中显示的“已引用资料”必须来自本轮 ContextManifest 或正文 citation，不能只因检索命中过就宣称模型使用了它。
- 旧文档版本被删除或更新后，历史请求仍引用原版本；物理清理前必须检查历史引用。
- 检索结果过长时执行用户可见的数量/范围选择，不自动随机截断。

## UI

- 知识库列表显示文档数、已索引数、embedding 配置、大小和最后更新时间。
- 文档表格显示版本、状态、片段数、失败原因和操作。
- 索引任务区域支持暂停、继续、取消和逐项重试。
- 会话输入区或右侧面板显示当前启用知识库。
- 每轮检索块显示查询、命中数量、纳入片段、分数、来源和耗时。
- 引用可跳转到只读片段查看器并定位版本/位置。
- 模块关闭后不显示入口；历史 retrieval 块用通用只读组件展示。

## 隐私与安全

- 仅处理用户明确选择的文件和目录项。
- 远程 embedding 前显示目标 Provider 和将上传的数据类型。
- 解析器把文件内容视为不可信，不执行脚本、宏或嵌入对象。
- 文档中的提示注入文本仍是资料，不提升为 system prompt 或客户端指令。
- 文件名和文档内容不直接形成 SQL、路径或 HTML。
- 删除知识库时分别确认元数据、索引、artifact 和历史引用范围。
- 导出知识库视为敏感数据；默认备份设置必须明确是否包含原文件和向量。

## 错误与恢复

- 解析失败：文档版本标记失败，保留原 artifact 和错误。
- embedding 部分失败：只重试缺失 chunk，已成功项以唯一键防重复。
- 应用退出：作业保存检查点，重启后由用户继续或按安全策略恢复。
- 模型维度变化：阻止写入旧索引并要求重建。
- sqlite-vec 不可用：模块显示不可用，不回退成伪向量或隐藏的 LIKE 检索。
- artifact 缺失/hash 不符：标记损坏并阻止引用该版本。
- 检索成功但 tool result 落库失败：不得继续生成并声称基于知识库回答。

## 性能

- 模块禁用时不加载 sqlite-vec、不启动索引 worker、不扫描文件。
- 解析和 embedding 使用有界队列、批次和背压。
- 大文件流式读取，避免在 React/Zustand 中保存整份正文。
- 向量查询和片段加载只返回需要的字段与数量。
- 索引任务不得阻塞聊天流式渲染；并发和 CPU/网络占用可暂停。
- 建立小、中、大 fixture，记录导入吞吐、查询延迟、峰值内存和取消释放。

## 自动化测试

- 文本/Markdown 解析、位置、chunk hash 和版本稳定性。
- 同内容去重、更新产生新版本、历史引用不漂移。
- 假 embedding Provider 的批次、重试、取消、维度不匹配。
- sqlite-vec 查询与确定性 fixture 排序。
- 检索候选、用户排除和最终 `modelContent` 一致。
- 知识库 tool result 跨轮 canary。
- 未知 embedding 模型和自定义参数透传。
- 远程 embedding 隐私提示与 secret 扫描。
- 解析恶意文件名、超大文件和提示注入内容。
- 索引中断恢复、删除和重建。
- 模块关闭后的零扫描、零后台任务和核心聊天可用性。

## 验收标准

- 用户能从最终回答的引用追踪到准确文档版本和片段。
- 开发者检查器能证明模型请求包含所显示的检索 `modelContent`。
- 第一轮知识库结果未被助手复述时，下一轮仍可按当前分支回放真实片段。
- 文档更新、重建索引和切换 embedding 模型不会改写历史证据。
- 用户未启用知识库时，不发生文件扫描、embedding 请求或向量模块常驻加载。
- 任何外发文件内容的行为在 UI 中可见且目标明确。
