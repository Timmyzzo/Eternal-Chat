# 提示词与助手预设

## 状态

- 里程碑：V1
- 当前状态：`deferred`
- 依赖：会话设置、参数三层合并、功能模块注册、导入导出

## 用户问题

普通用户需要复用常用指令和模型配置，高级用户需要知道某次请求究竟采用了哪个提示词版本、模型和参数。简单的“助手模板”如果会在后台实时变化或隐式覆盖会话设置，会让历史请求无法复现。

## 目标

- 提供可搜索、可分类、可复制的提示词库。
- 提供由提示词、默认模型和参数组成的助手预设。
- 把预设解析为明确的会话配置，不在发送时进行不可见改写。
- 支持简单、可校验的命名变量，并在发送前完成替换确认。
- 保存提示词修订和请求实际使用的解析结果。
- 支持安全导入导出，不包含 Provider 密钥。

## 非目标

- V1 不做公共提示词市场、云账号发布或评分系统。
- 不做可执行 JavaScript、模板宏、shell 命令或任意表达式。
- 不做自动提示词优化、自动改写用户输入或多代理工作流编排。
- 不把助手预设当成模型能力白名单。
- 不因修改模板而追溯改变既有会话和历史请求。

## 概念

### 提示词模板

一段可版本化的 system/user 提示词内容，可带有限的命名变量、标签、说明和适用场景。模板不强制绑定连接、端点或模型；凭据处理不属于提示词功能。

### 助手预设

面向新会话的配置集合，可包含：

- 显示名称和图标/颜色引用。
- 一个明确版本的 system prompt 模板。
- 可选 Provider/模型建议。
- 常用参数和 `extra_body`。
- 上下文策略建议，默认仍为 `lossless`。
- V2 模块可用后的可选工具或知识库引用。

助手预设是配置便利层，不是新的消息协议或独立 agent runtime。

### 解析快照

把模板变量、预设和会话覆盖合并后得到的实际 system prompt 与参数。每次请求的 RequestSnapshot 必须记录解析后的内容 hash、来源和版本；不能只记录一个可能已被修改的模板 ID。

## 用户流程

### 创建提示词

1. 用户创建名称、正文、用途和标签。
2. 客户端识别命名变量并要求定义类型、默认值和是否必填。
3. 保存时创建新修订，不覆盖已被历史请求引用的修订。
4. 用户可预览变量替换后的纯文本。

### 创建助手预设

1. 选择一个提示词修订或直接输入 system prompt。
2. 可选选择 Provider/模型，并配置参数 schema 中的值和 `extra_body`。
3. 客户端显示最终配置来源和冲突。
4. 保存后可从新建会话入口选择该预设。

### 应用到会话

1. 新会话应用预设时复制解析后的配置和来源引用。
2. 已有会话应用预设前显示将改变的 system prompt、模型和参数。
3. 用户确认后只影响后续请求，不修改历史 Message 或 RequestSnapshot。
4. 后续编辑模板不会自动改变该会话；用户可主动升级并查看差异。

## 合并与优先级

配置优先级与 [Provider 与模型参数规范](../PROVIDER_AND_MODEL_PARAMETERS.md) 一致：

1. 应用 baseline 默认值。
2. 助手预设建议值。
3. 模型级用户配置。
4. 会话级显式覆盖。
5. 当前请求的一次性覆盖。

后层只覆盖明确设置的字段。`extra_body` 仍遵循安全深合并和原型污染防护。UI 必须显示最终值来自哪一层。

助手预设不得把未知模型的 `reasoning_effort: xhigh` 删除、降级或隐藏。模型不可用时显示缺失配置，让用户重新选择或继续编辑，而不是替换成内置“相近模型”。

## 变量规则

- 仅支持声明过的命名变量，不执行表达式。
- 变量值按纯文本处理，不能改变 JSON 结构、角色或消息边界。
- 必填变量未提供时阻止发送。
- 模板变量只用于显式内容和运行参数；长期凭据如何保存由后续安全专题决定。
- 预览必须准确显示最终文本，避免在网络请求阶段再次发生不同替换。
- 变量解析失败时保留用户输入和模板版本，不回退到未解析占位符发送。

具体占位符语法在实现前固定为单一形式并加入迁移测试；不得同时支持多套含糊语法。

## 数据与版本

V1 migration 应增加独立的提示词、提示词修订和助手预设记录。语义要求：

- 模板 ID 稳定，每次正文变化产生 revision。
- revision 保存正文、变量 schema、hash 和创建时间。
- 助手预设引用明确 revision，并保存参数 JSON 和可选模型引用。
- 会话保存应用时的解析结果和来源，不依赖实时读取最新版模板。
- 删除模板默认只从库中隐藏；仍被历史或预设引用的 revision 保留。
- 导入冲突创建新 ID 或要求用户选择，不静默覆盖同名模板。

## UI

- 提示词库使用列表/表格与编辑区，不把每个字段拆成嵌套卡片。
- 支持搜索、标签、收藏、复制和修订记录。
- 新建会话可从简洁的助手选择器开始，也可直接使用普通空会话。
- 会话右侧面板显示当前预设来源、是否已偏离，以及“查看差异/主动升级”。
- 参数冲突、缺失 Provider、缺失变量和 V2 模块未启用都使用页面内状态说明。
- 普通聊天入口不能因存在预设系统而增加必填步骤。

## 模块依赖

提示词库和助手管理作为可关闭模块懒加载。核心聊天仍保留基础 system prompt 文本框。

当预设引用尚未启用的 MCP 或知识库模块时：

- 预设仍可查看和编辑。
- 应用前列出未满足依赖。
- 不自动启用模块或申请权限。
- 用户可以移除依赖后使用其余配置。
- 历史中已解析的 prompt 和参数仍可查看。

## 隐私与安全

- 提示词和预设属于本地敏感数据，默认不上传。
- 导出前显示将包含的正文、参数和模块引用；认证字段的导出规则由后续安全专题决定。
- 导入内容按不可信 JSON 和 Markdown 处理，校验大小、深度和 schema。
- 模板正文不能获得额外文件、网络或工具权限。
- 外部来源模板不得被标记为“官方”或“安全”，除非有可验证来源机制。

## 错误与恢复

- 模板 revision 损坏：阻止应用，已有解析快照仍可读取。
- 引用模型不存在：保留预设并标记待修复。
- 参数 schema 已变化：显示旧值、无效项和迁移选择，不静默删除。
- 变量未解析：阻止发送并聚焦缺失字段。
- 导入冲突：提供复制为新模板或逐项选择。
- 模块关闭：不丢失预设中的模块引用，但不得执行对应能力。

## 自动化测试

- 模板创建、修订、复制、搜索和软删除。
- 历史请求引用旧 revision 时修改模板不改变 RequestSnapshot。
- 变量必填、默认值、纯文本转义和失败阻断。
- 参数优先级、`extra_body` 深合并和来源展示。
- 未知模型与 `xhigh` 保持原值。
- 应用预设只影响后续请求，不修改历史分支。
- 缺失 Provider、模型、模块和参数 schema 的恢复。
- 导入导出 round trip、冲突和 secret 扫描。
- 模块关闭后核心聊天仍可使用基础 system prompt。

## 验收标准

- 用户能证明某次请求使用了哪个模板 revision、变量解析结果和参数来源。
- 修改提示词库不会改变已经发送的请求或现有会话，除非用户主动确认升级。
- 助手预设不会限制目录外模型或删除未知参数。
- 关闭提示词/助手模块后，其路由、按钮、订阅和后台任务不加载，核心聊天不受影响。
- 导入模板只恢复声明式内容、变量和元数据，不能执行代码或修改端点认证配置。
