# 会话库与搜索

## 状态

- 里程碑：MVP
- 当前状态：`specified`
- 依赖：SQLite、分页、FTS/LIKE、分支定位

## 用户问题

长期使用后，用户需要快速找到、整理和恢复会话。会话库不能为了显示列表而加载全部消息，也不能在搜索定位时丢失分支上下文。

## 目标

- 最近会话、置顶、归档、重命名和删除。
- 按标题和消息正文搜索。
- 搜索结果定位到消息和分支。
- 稳定分页和低内存。
- 当前生成状态在侧栏可见。

## 非目标

- MVP 不做云端协作标签体系。
- MVP 不做复杂文件夹嵌套。
- MVP 不做 AI 自动知识图谱。
- 消息级永久删除延后。

## 会话列表

默认按：置顶优先，然后 `updated_at DESC`。归档会话从主列表隐藏，可在归档视图搜索。

会话项显示标题、更新时间和少量状态。标题为空时使用首条用户消息的受限片段；后续自动标题不覆盖手工标题。

## 操作

- 新建。
- 重命名。
- 置顶/取消置顶。
- 归档/恢复。
- 导出单会话。
- 删除整个会话。

删除显示消息/附件数量估算，并说明 key 不受影响。完成后 artifact 延迟垃圾回收。

## 搜索

### 输入

支持关键词、短语和基础 role/filter 后续扩展。MVP 可以先提供全文关键词和归档范围。

### 结果

显示标题、命中片段、角色、时间和会话状态。点击：

1. 打开会话。
2. 切换到包含该消息的分支。
3. 分页加载所需范围。
4. 滚动并聚焦消息。

### 索引

优先 FTS5，无法使用时回退 LIKE 并显示能力状态。索引是派生数据，可重建。

## 分页

- 会话列表按 `(updated_at, id)` 游标。
- 消息按 `(created_at, id)` 游标。
- 不使用 offset 作为大型列表的长期方案。
- 加载更多时保持滚动锚点。

## 数据一致性

- 会话 `updated_at` 在新消息、标题、归档和分支 active leaf 变化时更新。
- 搜索索引与 message 事务或可靠异步队列同步。
- 索引失败不阻止消息保存，但显示可重建状态。

## UI

- 左侧会话栏。
- 搜索/命令面板。
- 归档 tab。
- 空结果和索引重建状态。
- 当前流式会话状态点。

## 错误

- FTS 不可用：回退并告知。
- 索引损坏：提供重建。
- 搜索定位消息已删除：刷新结果。
- 删除失败：保持列表项并显示错误。
- 会话数据损坏：进入只读诊断，不自动删除。

## 性能

- 侧栏虚拟化可在真实数量需要时加入，不提前复杂化。
- 搜索 debounce。
- 片段生成限制长度。
- 不加载完整 blocks/raw result 生成列表预览。

## 测试

- 排序、置顶、归档。
- 游标分页无重复/遗漏。
- FTS/LIKE 同一 fixture 结果。
- 搜索定位分支。
- 自动标题不覆盖手工标题。
- 删除事务和 artifact 引用。
- 1000 会话/大量消息查询基准。

## 验收标准

- 用户在 1000 条消息会话中搜索并定位目标。
- 归档和主列表结果正确。
- 搜索不会把其他 sibling 分支错误展示为当前路径。
- 会话列表和消息打开符合性能预算。
